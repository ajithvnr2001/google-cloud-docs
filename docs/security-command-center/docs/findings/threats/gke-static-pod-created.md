## Overview

Someone created a static Pod in your GKE cluster. Static Pods run directly on the node and bypass the Kubernetes API server, which make them more difficult to monitor and control. This could be used by attackers to evade detection or maintain persistence.

[Event Threat Detection](https://docs.cloud.google.com/security-command-center/docs/concepts-event-threat-detection-overview) is the source of this finding.

## How to respond

To respond to this finding, do the following:

  1. Review the static Pod's manifest file and its purpose. Verify that it is legitimate and necessary.
  2. Evaluate if the static Pod's functionality can be achieved through a regular Pod managed by the Kubernetes API server.
  3. If the static Pod is required, ensure that it follows security best practices and has minimal privileges.
  4. Monitor the static Pod's activity and its impact on your cluster.
