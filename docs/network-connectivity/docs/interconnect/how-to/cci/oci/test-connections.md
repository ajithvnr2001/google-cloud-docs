To check connectivity between your Google Cloud and OCI networks, complete the following tasks. By verifying these connections, you confirm proper setup and can troubleshoot any connectivity issues, ensuring reliable hybrid cloud operations.

## Check for a signal from OCI

In Google Cloud, check to see whether your Cross-Cloud Interconnect port is receiving a signal from the FastConnect port. 

### Console

  1. In the Google Cloud console, go to the Cloud Interconnect **Physical connections** page. 

[Go to **Physical connections**](https://console.cloud.google.com/hybrid/interconnects/list?tab=interconnects)

  2. Click the name of your primary Cross-Cloud Interconnect connection.
  3. On the **Interconnect details** page, locate the **Link circuit info** table. Check the **Receiving Optical Power** column. This column indicates whether the Cross-Cloud Interconnect connection is receiving input from the OCI port. The value in this column should be **OK**. 
  4. Repeat the preceding steps for your redundant Cross-Cloud Interconnect connection.



## Check the BGP sessions

Make sure that your BGP sessions are up. Check the session state in both OCI and Google Cloud.

### Verify the session in OCI

To check the session state in OCI, use the following steps. Complete these steps twice, once for each FastConnect resource.

###  Console 

  1. In the menu menu, select **Networking**. In the **Customer connectivity** navigation, select **FastConnect**.
  2. Click the name of the appropriate FastConnect resource.
  3. Click **Virtual circuits**. The page updates to include additional options.
  4. On the **Virtual circuit information** tab, locate the **IPv4 BGP state** field. It should be **Up**.



### Verify the session in Google Cloud

To check the session state in Google Cloud, use the following steps. Complete these steps twice, once for each Google Cloud VLAN attachment.

###  Console 

  1. In the Google Cloud console, go to the Cloud Interconnect **VLAN attachments** page.

[Go to VLAN attachments](https://console.cloud.google.com/hybrid/interconnects/list?tab=attachments)

  2. Click the name of your primary VLAN attachment.

  3. On the **VLAN attachment details** page, locate the **Status** field. It should be **Up**.




## Check your route tables

Look at your route tables in both OCI and Google Cloud.

### Check the OCI route table

In OCI, make sure that you see the Google Cloud routes that you expect.

###  Console 

  1. In the menu menu, select **Networking**. In the **Customer connectivity** navigation, select **Dynamic routing gateway**.
  2. Click the name of the appropriate DRG.
  3. In the list of attachments, look for the name of your VCN, and then click the **Autogenerated Drg Route Table for VCN attachments** link.
  4. Click **Get all routes**.



If you don't see the results that you expect, review the private virtual circuits that you created in OCI. Verify that you entered the correct values for each circuit, paying special attention to the values for **Customer BGP IPv4 address** , **BGP Peer IP** , and **VLAN**. Then check the route table again.

### Check the Google Cloud route table

In Google Cloud, make sure that you see the OCI routes that you expect.

###  Console 

  1. In the Google Cloud console, go to the **VPC networks** page.

[Go to VPC networks](https://console.cloud.google.com/networking/networks/list)

  2. Click the name of your network.

  3. Click the **Routes** tab. Verify that the routes from your OCI network show up as expected.
