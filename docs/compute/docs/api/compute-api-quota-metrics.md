#  Compute Engine API quota metrics reference Stay organized with collections  Save and categorize content based on your preferences. 

This page provides a list of the Compute Engine API quota metrics that are used to count requests to the API.

The Compute Engine API uses a static cost-based quota configuration. In this quota system, the API quota is charged based on the complexity of serving a request, rather than the number of requests. This means that complex requests, such as `regions.list` and `interconnectLocations.list`, require a higher token cost than requests such as `firewalls.list` and `backendBuckets.get`. This approach ensures a fair allocation of resources, aligning cost with the actual computational effort for each request.

**Note:** The information on this page applies only to the simplified Compute Engine API quotas. For methods that use the legacy Compute Engine API quota, the token cost is `1`. For more information about these quotas, see [Rate quotas](https://docs.cloud.google.com/compute/api-quota#api-rate-limits).
