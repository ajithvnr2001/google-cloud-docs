#  Locations for observability buckets Stay organized with collections  Save and categorize content based on your preferences. 

This page explains how regionality applies to data that is stored in an observability bucket. It also lists the geographical locations for these buckets.

## Overview

[Observability buckets](https://docs.cloud.google.com/stackdriver/docs/observability/storage-overview#storage-model) are regional resources. These resources can store data generated by Google Cloud services, like Cloud Trace. With the exception of observability buckets in the `eu` or `us` regions, Google Cloud manages the infrastructure so that your applications are available redundantly across the zones within the region.

You can specify the location and encryption model for observability buckets by configuring default settings for observability buckets. These settings can be defined at the organization, folder, and project level. Unless you set the default settings for observability buckets for a resource, that resource automatically inherit the default settings for observability buckets of their parent.

If you have data residency requirements, then don't enable services that can query data stored in an observability bucket and then store the query result in a `global` location. An example of such a service is [Gemini Cloud Assist](https://docs.cloud.google.com/gemini/docs/discover/certifications#cloud-assist-security).

## Supported regions

The following [regions](https://docs.cloud.google.com/docs/geography-and-regions#regions_and_zones) are supported for observability buckets.

### Multi-regions: EU and US

Region name | Region description  
---|---  
`eu` | Data is stored in any data center within the European Union. Data might be moved to different data centers. No additional redundancy guarantees.  
`us` | Data is stored in any data center within the United States. Data might be moved to different data centers. No additional redundancy guarantees.
