#  Change SAP HANA protection from volume level backup (LVM CBT) to Persistent Disk snapshot Stay organized with collections  Save and categorize content based on your preferences. 

**Caution:** Support for backing up and restoring workloads managed using the legacy appliance management console is deprecated. For more information, see [Feature deprecations](https://docs.cloud.google.com/backup-disaster-recovery/docs/deprecations).

An SAP HANA database that is performing database and log backups using volume level backup as per the defined schedule can have its protection changed to Persistent Disk snapshot.

The following steps outline how to change the protection method of an SAP HANA database from the Volume Level Backup capture method to Persistent Disk snapshot.

There are two ways to move to Persistent Disk snapshot protection. 

  * No database downtime but logs must be copied manually: Some logs won't be fully backed up by Backup and DR, so you must manually copy them to a safe place in case recovery becomes necessary.
  * Shut down and restart the SAP application and database: All logs will be fully backed up and accessible.



## No database downtime but logs must be copied manually

In this procedure you take a final on-demand backup of the data, then remove the policy that calls for volume level protection and replace it with one that uses Persistent Disk snapshots and run another on-demand job.

  1. From the **App Manager** select **Applications**.
  2. Select the application and then click **Manage Backup Configuration**.
  3. Click the policy and select **Run Now**.
  4. From the **Monitor** > **Jobs** , ensure the job finishes successfully.
  5. From the **Manage Backup Configuration** page under **Apply** , select **Remove backup plan**.

**Note:** This step does not expire or delete any existing backups.
  6. Select a new template and profile and click **Apply backup plan**.

  7. For the **Backup capture method** select **Use Persistent Disk snapshot**.

  8. Save your changes.

**Note:** Make sure the template for Persistent Disk snapshot based backup has **Snapshot Location** and **Snapshot Type** set, and that both **REPLICATE LOGS** and **SEND LOGS TO ONVAULT POOL** are set to **No**.
  9. Run an on-demand database backup from the **Manage Backup Configuration** page.

  10. Copy any log backups generated by SAP HANA database between Step #3 and Step #5 to a safe location until the log backup retention period as these logs won't be available to recover for the last backup using volume level backup.

**Note:** The old LVM backups will also be available in the backup list in the appliance management console until they expire.



## Shut down and restart the SAP application and database

  1. From the **App Manager** select **Applications**.
  2. Select the application and then click **Manage Backup Configuration**.
  3. Click the policy and select **Run Now**.
  4. From the **Monitor** > **Jobs** , ensure the job finishes successfully.
  5. Stop the SAP HANA database.
  6. From the **Manage Backup Configuration** page under **Apply** , select **Remove backup plan**.

**Note:** This step does not expire or delete any existing backups.
  7. Select a new template and profile and click **Apply backup plan**.

  8. For the **Backup capture method** select **Use Persistent Disk snapshot**.

  9. Save your changes.

**Note:** Make sure the template for Persistent Disk snapshot based backup has **Snapshot Location** and **Snapshot Type** set, and **REPLICATE LOGS** and **SEND LOGS TO ONVAULT POOL** are set to **No**.
  10. Start the SAP HANA database.

  11. Select the application and then click **Manage Backup Configuration**.

  12. Click the policy and select **Run Now**.

  13. From the **Monitor** > **Jobs** , ensure the job finishes successfully.

  14. Resume normal operations of your SAP application.


**Note:** The old LVM backup will also be available in the backup list on the appliance management console until it expires.
