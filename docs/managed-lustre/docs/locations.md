#  Supported locations Stay organized with collections  Save and categorize content based on your preferences. 

Google Cloud Managed Lustre instances live in zones within regions. A region is a specific geographical location where you can run your resources. Each region is subdivided into several zones. For example, the `us-central1` region in the central United States has zones `us-central1-a`, `us-central1-b`, `us-central1-c`, and `us-central1-f`. For more information, see [Geography and regions](https://docs.cloud.google.com/docs/geography-and-regions).

Some Google Cloud APIs, including the Managed Lustre API, use the concept of locations, which can represent either [regions or zones](https://docs.cloud.google.com/storage/docs/locations#key-concepts). For Google Cloud Managed Lustre instances, locations map to zones.

To decrease network latency, we recommend creating a Managed Lustre instance in a region and zone that is close to where you plan to use it. For example, if you plan to access the instance from Asia, then you should create it in one of the `asia-east1` zones. Similarly, you get the best performance by mounting Managed Lustre instances on clients in the same region.
