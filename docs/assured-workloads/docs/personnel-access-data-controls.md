# Personnel data access and support controls

This page provides information about personnel data access in Assured Workloads, which provides control over Google personnel's access to Customer Data and support case assignments. Assured Workloads provides the following controls based on the [control package](https://docs.cloud.google.com/assured-workloads/docs/control-packages) you choose:

  * Personnel data access controls
  * Personnel support case ownership controls based on attributes

**Important:** Don't include confidential, sensitive, or personally identifiable information in project names, project IDs, resource names, or other resource fields. Unless otherwise noted in the documentation or [service specific terms](https://cloud.google.com/terms/service-terms) for a supported product or service, data included in these fields doesn't constitute Customer Data, and is out of scope for Assured Workloads' personnel data access controls.

### Personnel data access controls

Personnel data access controls ensure that only Google personnel who are able to satisfy certain physical location and background check requirements are able to access customer data in the course of a support action. For example, Impact Level 4 (IL4) requires US Persons to have completed an ADP-1 Single Scope Background Investigation (SSBI) background investigation before they can access data in an approved IL4 environment.

### Personnel support case ownership controls based on attributes

Personnel support case ownership controls based on attributes ensures that only Google support personnel who satisfy certain requirements are assigned to support cases for Assured Workloads customers.
