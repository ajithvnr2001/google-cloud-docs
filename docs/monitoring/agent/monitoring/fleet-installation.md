**Caution:** As of September 28, 2026, the legacy Monitoring agent has reached its end of support. Standard maintenance and bug fixes are no longer provided. We strongly recommend migrating to one of the [supported alternatives](https://docs.cloud.google.com/monitoring/agent/). For more information about this deprecation, see [Legacy Monitoring and Logging agents end of support](https://docs.cloud.google.com/stackdriver/docs/deprecations/legacy-agents). 

In addition to using the Google Cloud CLI or Terraform to create [agent policies](https://docs.cloud.google.com/monitoring/agent/monitoring/managing-agent-policies), you can use other automation tools to manage the Monitoring agent across your fleet of Compute Engine VMs:

  * **Ansible** by using the Ansible role, you can install and configure the agent across your fleet of Linux VMs. For more information, see the [Ansible Role for Cloud Ops](https://github.com/GoogleCloudPlatform/google-cloud-ops-agents-ansible#ansible-role-for-cloud-ops) documentation. 
  * **Chef** : by using the Chef cookbook, you can install and configure the agent across your fleet of Linux VMs. For more information, see the [Chef Integration](https://github.com/GoogleCloudPlatform/google-cloud-ops-agents-chef/blob/master/README.md) documentation. 
  * **Puppet** : by using the Puppet module, you can install and configure the agent across your fleet of Linux VMs. For more information, see the [Puppet Integration](https://github.com/GoogleCloudPlatform/google-cloud-ops-agents-puppet/blob/master/README.md) documentation.
