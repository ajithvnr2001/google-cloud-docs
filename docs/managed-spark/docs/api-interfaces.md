You can use one of several programmatic interfaces when interacting with Managed Service for Apache Spark. These are the available interfaces, in the order that we recommend using them:

  * [Google Cloud Client Libraries](https://docs.cloud.google.com/apis/docs/client-libraries-explained#google_cloud_client_libraries): Managed Service for Apache Spark ([alpha and beta release](https://cloud.google.com/terms/launch-stages#launch-stages)) client libraries are available in multiple languages and are built on [gRPC](https://grpc.io/). These client libraries provide a layer of abstraction on top of gRPC and handle the details of operation polling, retries, and more.

**Note:** Although the Cloud Client Libraries are the preferred library choice, [Google API Client Libraries](https://developers.google.com/api-client-library/) for Managed Service for Apache Spark are also available. These "legacy" libraries access REST but not gRPC APIs (see [Google API Client Libraries](https://docs.cloud.google.com/apis/docs/client-libraries-explained#google_api_client_libraries) for additional information).
  * [gRPC](https://docs.cloud.google.com/managed-spark/docs/reference/rpc): If a client library is not available for your programming language of choice, you can generate gRPC client libraries for Dataproc in any gRPC-supported language. To do this, you'll need the [protocol buffers](https://developers.google.com/protocol-buffers/) service definition available from [our repository on GitHub](https://github.com/googleapis/googleapis). You can then follow the instructions for your preferred language on [grpc.io](https://grpc.io/) to generate and use your client.

  * [REST API](https://docs.cloud.google.com/managed-spark/docs/reference/rest): If you're unable to use Managed Service for Apache Spark's client libraries or the gRPC API, use the REST API.
