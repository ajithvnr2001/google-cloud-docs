# Bigtable locations

When you [create a Bigtable instance](https://docs.cloud.google.com/bigtable/docs/creating-instance), you must choose a _location_ for each cluster in the instance. You cannot change the location after you create the cluster.

Bigtable is available in _zonal locations_ , which are zones within a Google Cloud _region_. If a zone becomes unavailable, all of the zonal resources in that zone are unavailable until service is restored.

To reduce latency and increase availability, store your data close to the users and services that need it. For example, if you frequently write data to Bigtable from a Cloud Storage bucket in the `us-central1` (Iowa) region, create your Bigtable cluster in a zone within `us-central1`.
