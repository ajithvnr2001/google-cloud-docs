## 21.20

Changed  The **Use old dashboards routes** [legacy feature](https://docs.cloud.google.com/looker/docs/legacy-feature-schedule) now defaults to off.  Changed  After [saving an Explore to a dashboard](https://docs.cloud.google.com/looker/docs/creating-user-defined-dashboards#adding_query_tiles_from_an_explore), users who click the dashboard link from the confirmation banner will enter the dashboard in [edit mode](https://docs.cloud.google.com/looker/docs/editing-user-defined-dashboards#entering_edit_mode_in_dashboards).  Changed  When a user attempts to navigate away from a dashboard that has unsaved changes, the user will [now see a **Discard changes?** warning dialog](https://docs.cloud.google.com/looker/docs/editing-user-defined-dashboards#entering_edit_mode_in_dashboards).  Changed  A new legacy feature, **Use old navigation and legacy routing** , allows you to disable enhanced navigation, which is now the default navigation experience. The **Use old navigation and legacy routing** [legacy feature](https://docs.cloud.google.com/looker/docs/legacy-feature-schedule#legacy_feature_schedule) will be removed starting in Looker 22.2.  Changed  The default [alerts](https://docs.cloud.google.com/looker/docs/alerts-overview) experience now includes all the features and capabilities of enhanced alerts without the need to enable a [Labs feature](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs).  Changed  In order to address a vulnerability, Looker no longer recognizes self-closing XHTML tags in custom visualizations. Enabling a new legacy feature, **Allow XHTML-style Empty Tags in Custom Visualizations** , causes self-closing XHTML tags to be recognized in custom visualizations, but also exposes the vulnerability. For more information, see the [Allowing XHTML-style empty tags in custom visualizations](https://docs.cloud.google.com/looker/docs/best-practices/how-to-use-allow-xhtml-style-empty-tags-in-custom-visualizations-legacy-feature) Best Practices page.  Added  Looker has improved **Dark Mode** visualization styling for [single value](https://docs.cloud.google.com/looker/docs/single-value-options), Cartesian, [pie](https://docs.cloud.google.com/looker/docs/pie-options), and [donut multiples](https://docs.cloud.google.com/looker/docs/donut-multiples-options) charts.  Added  A new [details panel](https://docs.cloud.google.com/looker/docs/viewing-dashboards#dashboard_details) is available for dashboards, including a new area where you can add a description for the dashboard. Metadata that shows the user who created and updated the dashboard, along with the number of favorites and views, also appears.  Added  The new **Guided analyses in System Activity** [Labs feature](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#guided_analyses_in_system_activity) provides the option to leverage a question-and-answer format for [performing analyses](https://docs.cloud.google.com/looker/docs/usage-reports-with-system-activity-explores#guided_analysis) in the **History** System Activity Explore.  Added  The **Dashboard** System Activity Explore now includes the `preferred_viewer` parameter and also mitigates an issue where the `is_legacy` field was not accounting for nulls.  Added  Looker now supports the [`approximate`](https://docs.cloud.google.com/looker/docs/reference/param-field-approximate) parameter for the Google BigQuery Standard SQL dialect.  Added  The **LookML New Runtime (Aragonite)** Labs toggle enables the option to use Aragonite on the Looker instance. When this Labs feature is enabled (the default), LookML developers can turn on Aragonite for individual LookML projects on the instance by adding the `aragonite: yes` statement to a project's manifest file.  Added  A new error message warns users when they attempt to use Liquid templates in the `value_format` parameter.  Added  The **Dashboard Details** description in the new [Dashboard Details panel](https://docs.cloud.google.com/looker/docs/viewing-dashboards#dashboard_details) uses the same API as previous descriptions.  Added  Looker dialect MySQL 8.0.12+ now supports [incremental PDTs](https://docs.cloud.google.com/looker/docs/incremental-pdts).  Added  A new endpoint to the Looker SDK lets users request a dependency graph for a PDT.  Added  Looker has introduced a new LookML parameter, `interval_trigger`. The `interval_trigger` parameter specifies an interval at which a derived table is triggered for rebuild. `interval_trigger` can be a subparameter of [`datagroup`](https://docs.cloud.google.com/looker/docs/reference/param-model-datagroup#interval_trigger) or [`derived_table`](https://docs.cloud.google.com/looker/docs/reference/param-view-interval-trigger), and it accepts an interval string that indicates a number of seconds, minutes, or hours (such as `"24 hours"`).  Added  The [PDT details modal](https://docs.cloud.google.com/looker/docs/admin-panel-database-pdts#pdt_details_modal) now includes a **Show Dependency Graph** button that displays a relationship diagram with the names and statuses of any [cascading derived tables](https://docs.cloud.google.com/looker/docs/derived-tables#cascading_derived_tables) that the PDT depends on.  Fixed  In a [nested menu](https://looker-open-source.github.io/components/latest/?path=/docs/docs-menu--docs), the parent menu item now remains highlighted.  Fixed  Clicking a [menu item](https://looker-open-source.github.io/components/latest/?path=/docs/docs-menu--docs) with a nested menu will not close both menus.  Fixed  An issue has been fixed where previously LDAP groups that were prefixed with `#` were causing errors.  Fixed  An error message in beta users pages that stated `"user never logged in"` for users who had logged in via SAML has been fixed.  Fixed  Performance issues with the group selector on the user edit pages have been fixed. This required a slight change to the design, but the overall UX is the same.  Fixed  Looker now accepts any valid certificate trust path when verifying SSL/TLS certificates, rather than failing if there is an invalid and valid path in the same chain presented from the server.  Fixed  Erroneous dates, such as `January 1900`, no longer appear in query results when a user downloads results in CSV format.  Fixed  The `run_query` API endpoint now renders an empty result set instead of returning an error stating that `"The response body could not be parsed"`.  Fixed  Using the parameter `value_format_name` now rounds to the specified floating point precision.  Fixed  Downloading results in XLSX format no longer renders numbers using exponential notation.  Fixed  An issue has been fixed that caused certain System Activity queries from the **History** Explore to return a primary key error.  Fixed  An issue has been fixed that allowed the `system_activity` model to be selected while model sets were being edited. 

## 21.18

Changed  **Deleted Date** has been changed to **Moved to Trash Date** in the Look and Dashboard usage views of the System Activity Content Usage Explores to differentiate between soft deletion (trash) and hard deletion (absolute).  Changed  The **Revert to Legacy Dashboards** [legacy feature](https://docs.cloud.google.com/looker/docs/legacy-feature-schedule#enabling_and_disabling_legacy_features) has been [extended](https://docs.cloud.google.com/looker/docs/legacy-feature-schedule#legacy_feature_schedule) until Looker 22.0.  Changed  For Looker connections to [Microsoft SQL Server (MSSQL)](https://docs.cloud.google.com/looker/docs/db-config-microsoft-sql-server), [Microsoft Azure Synapse Analytics](https://docs.cloud.google.com/looker/docs/db-config-microsoft-azure-synapse-analytics), and [Microsoft Azure SQL Database](https://docs.cloud.google.com/looker/docs/db-config-microsoft-azure-sql-database), if you need to specify a non-default port other than 1433 and your database requires using a comma instead of a colon, you can add `useCommaHostPortSeparator=true` in the [**Additional Params**](https://docs.cloud.google.com/looker/docs/connecting-to-your-db#additional_params) field of Looker's **Connection Settings** page. This allows you to specify a non-default port other than 1433 in the [**Remote Host:Port** field](https://docs.cloud.google.com/looker/docs/connecting-to-your-db#remote_host:port).  Changed  The border color for the [`Button`](https://looker-open-source.github.io/components/latest/components/actions/button) component has been updated to improve contrast.  Changed  The border color for input [components](https://looker-open-source.github.io/components/latest/components/) has been updated to improve contrast.  Added  The following Looker Marketplace Blocks have been converted to a new structure that utilizes [LookML refinements](https://docs.cloud.google.com/looker/docs/lookml-refinements) rather than [extends](https://docs.cloud.google.com/looker/docs/reusing-code-with-extends) and are available for instances on Looker 21.8 or later: Retail Analytics, Google Ads Transfer, Jira, Shopify, Amazon Redshift Admin, Hubspot Marketing, Zendesk, Braintree Payments, Community Mobility, Campaign Manager 360, GitHub, Google Analytics 360, Search Ads 360, Chronicle, Google Cloud Audit Logs, Census Data, and BigQuery Info Schema. If your Looker instance has a version of one of these block installed that uses extends and you would like to install the version of the block that uses refinements, you can follow these instructions to [migrate any customizations](https://docs.cloud.google.com/looker/docs/marketplace-customize-blocks) your extends-based block may have.  Added  Looker now prevents schedules from re-running indefinitely if a schedule job is interrupted. Looker will attempt to re-run the job up to 10 times.  Added  A new Labs feature, **URL Links in Boards** , allows editors of boards to [add links to any URL](https://docs.cloud.google.com/looker/docs/presenting-content#adding_links_to_a_board) on a board alongside their existing Looks and dashboards.  Added  Users can now group alerts by alert owner or dashboard name on the [**Manage Alerts** user page](https://docs.cloud.google.com/looker/docs/user-alerts#grouping_alerts) and the [**Alerts** admin page](https://docs.cloud.google.com/looker/docs/admin-panel-alerts-and-schedules-alerts#grouping_alerts).  Added  Looker instances created with Looker 21.18 and later have the [`see_pdts`](https://docs.cloud.google.com/looker/docs/admin-panel-users-roles#see_pdts) permission added to the **Developer**[ default permission set](https://docs.cloud.google.com/looker/docs/admin-panel-users-roles#default_permission_sets).  Added  The option to **Convert Project to New LookML** has been re-introduced to the LookML IDE to allow users to [convert their YAML LookML to LookML](https://docs.cloud.google.com/looker/docs/best-practices/how-to-convert-yaml-to-new-lookml).  Added  Dremio and Dremio 11+ now support timezone conversions.  Added  Firebolt now supports in-database pivoting.  Added  Google ripple animation has been added to the `IconButton`, `Checkbox`, `Radio`, and `ToggleSwitch` components. The ripple is not visible when content is embedded.  Added  Within a Looker instance, [private embeds](https://docs.cloud.google.com/looker/docs/private-embedding) can now use the [Google OAuth](https://docs.cloud.google.com/looker/docs/admin-panel-authentication-google) and [OpenID Connect](https://docs.cloud.google.com/looker/docs/admin-panel-authentication-openid-connect) authentication flows to authenticate a user.  Fixed  A bug has been resolved where incremental PDTs with a `timezone` parameter would previousy generate timezone conversion incorrectly in the `WHERE` clause of an incremental PDT update.  Fixed  A bug has been resolved that previously caused text within a ` <link> ` tag in inline documentation to not be formatted with blue text.  Fixed  A bug has been resolved that previously caused the swatch in an [`InputColor`](https://looker-open-source.github.io/components/latest/components/forms/input-color) component to be incorrect when the field was disabled.  Fixed  A bug has been resolved for the Labs beta feature **LookML Dashboard Organization** that would cause LookML dashboards to not show up in the LookML dashboards folder if a customer had previously deleted LookML projects that contained LookML folders. 

## 21.16

Changed  The [**Enhanced Navigation**](https://docs.cloud.google.com/looker/docs/navigating-looker) Labs feature is now on by default for all customer instances.  Changed  The [**Custom Fields**](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#custom_fields) Labs feature has moved from experimental to beta.  Changed  When formatting is enabled for query downloads, JSON numeric values must be enclosed in quotes.  Changed  For PDTs that are persisted as [materialized views](https://docs.cloud.google.com/looker/docs/reference/param-view-materialized-view) on your database, the [**PDT Admin**](https://docs.cloud.google.com/looker/docs/admin-panel-database-pdts) page displays "Materialized View" under the PDT name in the PDT table, and displays "Materialized View" as the [persistence rule](https://docs.cloud.google.com/looker/docs/admin-panel-database-pdts#persistence_rule) in the PDT table and the [**PDT Details** modal](https://docs.cloud.google.com/looker/docs/admin-panel-database-pdts#pdt_details_modal).  Changed  The legacy field picker toggle has been removed.  Changed  A non-admin user can now be granted the [`see_alerts`](https://docs.cloud.google.com/looker/docs/admin-panel-users-roles#see_alerts) permission, which enables access to the [**Alerts** management page](https://docs.cloud.google.com/looker/docs/admin-panel-alerts-and-schedules-alerts) and the [**Alert History** page](https://docs.cloud.google.com/looker/docs/admin-panel-alerts-and-schedules-alert-history) in the **Admin** section of Looker. From the **Alerts** management page, they can view, follow, edit, self-assign, or delete any alert on the Looker instance.  Changed  Display-name-related attributes for alert owners and followers have been re-added to the public alert API.  Added  When enabled, a new experimental Labs toggle option, [**LookML Dashboard Organization**](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#lookml_dashboard_organization), lets users organize LookML dashboards into other folders besides the default folder, **LookML dashboards**.  Added  The [**Enhanced Navigation**](https://docs.cloud.google.com/looker/docs/navigating-looker) Labs feature allows [folders](https://docs.cloud.google.com/looker/docs/navigating-looker#folders) to be expanded in the [new enhanced left navigation panel](https://docs.cloud.google.com/looker/docs/navigating-looker#new_enhanced_navigation_changes). When the feature is enabled, the [**Admin**](https://docs.cloud.google.com/looker/docs/navigating-looker#for_admins:_accessing_the_admin_panel) menu is now an option in the left navigation panel instead of in the gear menu on the top navigation bar.  Added  The [stepped funnel visualization option](https://docs.cloud.google.com/looker/docs/funnel-options#stepped_funnel) has been re-introduced in new dashboards.  Added  New [dashboard settings](https://docs.cloud.google.com/looker/docs/editing-user-defined-dashboards#default_filters_view), **Expanded** and **Collapsed** , now let you choose the default appearance for dashboard filters.  Added  Users can now can copy a dashboard from within the dashboard itself using the [dashboard's three-dot menu](https://docs.cloud.google.com/looker/docs/viewing-dashboards#copying_dashboards).  Added  [Cross-filtering](https://docs.cloud.google.com/looker/docs/cross-filtering-dashboards) is now available for touchscreen devices. When cross-filtering is enabled for a dashboard, the **touch and hold** behavior will apply the filter.  Added  [**Always Retry Failed PDT Builds**](https://docs.cloud.google.com/looker/docs/connecting-to-your-db#always_retry_failed_pdt_builds) is a new checkbox in Looker's [connection settings](https://docs.cloud.google.com/looker/docs/connecting-to-your-db). When the **Always Retry Failed PDT Builds** setting is enabled, the [Looker regenerator](https://docs.cloud.google.com/looker/docs/derived-tables#the_looker_regenerator) will attempt to rebuild [trigger-persisted tables](https://docs.cloud.google.com/looker/docs/glossary#trigger-persisted-table) that failed in the previous regenerator cycle, even if a PDT's trigger value has not changed since the previous trigger check. **Always Retry Failed PDT Builds** is disabled by default.  Added  **Embed Users** credentials (for embed roles) and **Looker Support** credentials (for support roles) are now classified and displayed accordingly in the [**Edit Group**](https://docs.cloud.google.com/looker/docs/admin-panel-users-groups#editing_groups) page.  Added  [Legacy dashboards scheduled for delivery from within a folder](https://docs.cloud.google.com/looker/docs/delivering-legacy-dashboards#opening_the_scheduler_from_a_folder) will now use the same interface as new dashboards and alerts. The changes to the folders UI are cosmetic only; functionality is unchanged.  Fixed  The 12:00:00 PM timestamps now display as expected for XLSX downloads that use the new query streamers.  Fixed  Streamed queries no longer return a totals row if there are no results.  Fixed  Sorting the pivot keys of `type:long` using new query streamers now works as expected.  Fixed  Users can now see better performant filter suggestions when creating a new filter.  Fixed  The EULA statement is now readable on all instances as expected.  Fixed  The `Never logged in` label is now added correctly to SAML logins if the **New Users Page** experimental Labs feature is enabled.  Fixed  Connection tests no longer appear canceled when they contain errors.  Fixed  Users with custom email domains can now be added as expected using the `Add Users` setting in **New Users** page. 

## 21.14

Changed  Starting in Looker 21.14, the **Syntax Tolerant Liquid** legacy feature flag will be disabled for all users by default. Looker admins can continue to turn this warning off and on until October 2021, when the toggle will be removed.  Changed  The [**New Explore Visualizations** Labs feature](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#new_explore_visualizations) is now enabled by default.  Changed  The [Looker API](https://docs.cloud.google.com/looker/docs/api-intro) 4.0 is now designated as **beta** rather than **experimental**.  Changed  [Native derived tables](https://docs.cloud.google.com/looker/docs/derived-tables#native_derived_tables) that use the [`dev_filters`](https://docs.cloud.google.com/looker/docs/reference/param-view-explore-source#dev_filters) parameter are rebuilt in Development Mode only if a production version that satisfies the query does not exist.  Changed  MemSQL has been rebranded to **SingleStore**.  Changed  Starting August 13, 2021, [GitHub requires token authentication for all Git operations](https://github.blog/2020-12-15-token-authentication-requirements-for-git-operations/). For all LookML projects that use [GitHub with password authentication](https://docs.cloud.google.com/looker/docs/setting-up-git-connection#connecting_to_git_using_https), to successfully commit you need to [reset your Git connection in your project settings](https://docs.cloud.google.com/looker/docs/setting-up-git-connection#configuring_https_git_authentication) to use a personal access token.  Changed  When a user is deleted, any alerts they own are also deleted automatically and immediately.  Added  **Enhanced Alerts** is a [Labs feature](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#enhanced_alerts) that, when enabled, displays a new UI on the alert management pages for [users](https://docs.cloud.google.com/looker/docs/user-alerts) and [admins](https://docs.cloud.google.com/looker/docs/admin-panel-alerts-and-schedules-alerts), allows users to see more [details](https://docs.cloud.google.com/looker/docs/user-alerts#alert_details_page) about an alert, and enables Looker to sync an alert with [most changes](https://docs.cloud.google.com/looker/docs/effect-of-dashboard-edits-on-alerts) made to the alert's dashboard content.  Added  The [**Forecasting**](https://docs.cloud.google.com/looker/docs/forecasting-in-visualizations) Labs feature enables analysts to project analyses into the future without derived tables, table calculations, or custom code.  Added  [**Clear cache and refresh permission**](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#clear_cache_and_refresh_permission) is an experimental Labs feature that enables the `clear_cache_refresh` permission, which controls users' abilities to clear cache and refresh internal and embedded content.  Added  **Introducing[API Explorer](https://docs.cloud.google.com/looker/docs/api-explorer)**, our all new interactive API reference documentation that replaces the [**API Docs**](https://docs.cloud.google.com/looker/docs/legacy-feature-schedule#current_legacy_features) feature. Starting in 21.14, API Docs is a legacy feature; however, it can still be accessed with the **Require Authentication to Retrieve API Specifications** toggle.  Added  Users can now use the [**Bin**](https://docs.cloud.google.com/looker/docs/custom-fields#custom_binning) custom dimension type to create custom bins, or tiers, on numeric dimensions without the need to write complex LEXP expressions.  Added  The LookML dimension type [`bin`](https://docs.cloud.google.com/looker/docs/reference/param-dimension-filter-parameter-types#bin) has been introduced as an alias of the type [`tier`](https://docs.cloud.google.com/looker/docs/reference/param-dimension-filter-parameter-types#tier).  Added  Users can now use the [**Get link** option](https://docs.cloud.google.com/looker/docs/viewing-dashboards#getting_a_dashboards_link) under the dashboard **Actions** menu to easily share content and copy the correct URL.  Added  [Google Cloud Spanner](https://docs.cloud.google.com/looker/docs/db-config-cloud-spanner) is now a supported Looker dialect and no longer requires a JDBC driver to connect to the Spanner instance. It now supports query time zones, symmetric aggregates, and multiple `DISTINCT` columns in a single `SELECT` statement.  Added  In the [**PDT details** modal of the **Persistent Derived Tables**](https://docs.cloud.google.com/looker/docs/admin-panel-database-pdts#pdt_details_modal) admin page, users can now see the SQL that was used for the last build of a PDT.  Added  Admins can now create permission sets for users to include or exclude the ability to clear cache and refresh. By default, Looker users will have this permission enabled.  Fixed  The first tab of XLSX files that are downloaded with the new query streaming pipeline now show `Sheet1` as their sheet name.  Fixed  Using any time-related fields in the custom measure filter condition no longer creates unnecessary time zone conversions and works as expected.  Fixed  The [`sql_quote` Liquid filter](https://docs.cloud.google.com/looker/docs/liquid-variable-reference#require_sql_quote) now accepts arrays as input.  Fixed  For [document files](https://docs.cloud.google.com/looker/docs/other-project-files#document_files) in your Looker project, the IDE preview will now render the files in the same way that the files appear to your users. Before, the IDE preview corrected errors in HTML so that the preview might have looked correct even if the file had HTML errors that would have been visible in the final version. Now, if your document files have errors, the errors will be visible in the IDE preview.  Fixed  For projects with [advanced deploy mode](https://docs.cloud.google.com/looker/docs/advanced-deploy-mode), the [Git button](https://docs.cloud.google.com/looker/docs/git-command-reference) in the Looker IDE now shows [**Pull from Primary Branch**](https://docs.cloud.google.com/looker/docs/git-command-reference#pull_primary) when a development branch is behind the production branch and [**Merge to Primary Branch**](https://docs.cloud.google.com/looker/docs/git-command-reference#merge_primary) when there are unmerged commits on the developer branch. 

## 21.12

Changed  The error-message format has been enhanced for `value_format_name` and `value_format` parameter mismatches. Example: `Invalid 'value_format'. Error: 'decimal_1' is invalid for the 'value_format' parameter. Did you mean to use the 'value_format_name' parameter?` Changed  In the System Activity [**User** Explore](https://docs.cloud.google.com/looker/docs/usage-reports-with-system-activity-explores#user), the `Sessions` view now applies a default filter to remove "ephemeral" sessions that are used for rendering. This can be overridden, if necessary, by filtering on the `session.credential_type` dimension.  Changed  SQL Runner buttons will no longer be surfaced for [System Activity Explores](https://docs.cloud.google.com/looker/docs/usage-reports-with-system-activity-explores).  Changed  [Required filters](https://docs.cloud.google.com/looker/docs/filters-user-defined-dashboards#requiring_a_filter_value) that are type **popover** or **advanced** will now show `Value required` instead of `Any value`.  Changed  Users with the [`save_content`](https://docs.cloud.google.com/looker/docs/admin-panel-users-roles#save_content) permission now have the ability to add tiles to dashboards.  Changed  The **Make public...** keyboard shortcuts Command-Shift-P (Mac) and Ctrl+Shift+P (Windows) have been removed from Explores and Looks.  Changed  Fields of type `YesNo` will have user-written SQL wrapped in parentheses when the fields are used in a SQL filter.  Changed  The [**Render Long Tables**](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#render_long_tables) Labs setting for visualizations is now enabled by default. Additionally, for tables with more than 20,000 cells, [cell visualizations](https://docs.cloud.google.com/looker/docs/table-options#cell_visualization) as well as [conditional formatting](https://docs.cloud.google.com/looker/docs/table-options#enable_conditional_formatting) options other than **Background color** no longer appear in downloads or deliveries when the **Expand Tables to Show All Rows** option is selected.  Changed  To prevent merge conflicts, the Looker IDE does not present the [**Pull from (production branch)**](https://docs.cloud.google.com/looker/docs/git-command-reference#pull_prod) option to developers when the current developer branch has uncommitted changes.  Added  The new [**Redux DevTools** Labs feature](https://docs.cloud.google.com/looker/docs/admin-panel-general-labs#redux_devtools) enables debugging application state.  Added  New Quick Start analyses are now available for the [**History**](https://docs.cloud.google.com/looker/docs/usage-reports-with-system-activity-explores#history) and [**Dashboard**](https://docs.cloud.google.com/looker/docs/usage-reports-with-system-activity-explores#dashboard) System Activity Explores.  Added  The `Role List` measure is now available in the `Role` view in the System Activity model. It provides an aggregated list of the `role.name` field.  Added  Users are now able to [add Looks](https://docs.cloud.google.com/looker/docs/adding-saved-content-to-dashboards-legacy-feature) directly to dashboards with the **Add Looks to dashboards** [legacy feature](https://docs.cloud.google.com/looker/docs/legacy-feature-schedule#current_legacy_features) toggle enabled.  Added  [Two new integrations](https://docs.cloud.google.com/looker/docs/admin-panel-platform-actions#list_of_integrated_services) are available from the Looker Action Hub: Google Ads Customer Match and Google Analytics Data Import. See the **Actions** page in the **Admin** panel to enable these actions. These actions are available for instances on Looker 7.4 and later.  Added  [**Auto Install**](https://docs.cloud.google.com/looker/docs/admin-panel-platform-marketplace#auto_install) is a new toggle setting that has been introduced to the Marketplace settings. **Auto Install** allows for the auto installation of a suite of fundamental Looker-built applications (for example, API Explorer).  Added  The Looker [extension framework](https://docs.cloud.google.com/looker/docs/extension-framework) is out of Labs and now generally available under the [Admin > Platform](https://docs.cloud.google.com/looker/docs/admin-panel-platform-extension-framework) settings. The extension framework is a development framework that significantly reduces the effort and complexity of building data applications with Looker.  Added  Admins now have the ability to move content to the trash in bulk in the **Unused Content** page.  Added  A new Labs feature, [Enhanced Navigation](https://docs.cloud.google.com/looker/docs/navigating-looker), simplifies user workflows with unified left-hand navigation and more performant routing between common pages and content.
